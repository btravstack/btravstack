# @btravstack/entity

Optional domain-modelling package. It depends on Zod, unthrown and `@unthrown/standard-schema` as peers and has no dependency on any other btravstack package. Its public root is the `Entity` facade, with top-level type exports required by declaration emit. The [entity guide](../../docs/entity/index.md) and [API config](../../docs/typedoc.entity.json) own its published explanation and signatures.

The builder derives `input`, `output`, `createInput` and `updateInput` from one field map. Construction, update and rehydration converge on the same validation and invariant path; data is frozen and a result carries structured `InvalidEntity` issues. Aggregate roots use events and sealed decisions, with version checks and persistence left to an adapter. No I/O belongs in this package. Entity fields are nominal unless explicitly marked unbranded.

Three aggregate and projection decisions adapters lean on. `emit` and `start` are typed by the event union's `z.input`, because both parse before folding; handlers and `Decision.events` see the output. A terminal event is declared in `ends`, never inferred from a `type` string: it sets `Decision.isTerminal`, and nothing is decided after it (`emit` refuses it at compile time, an ended state's `emit` is a defect, `replay` refuses a stream that continues past it). `toJSON()` is canonical, so adapters can diff two projections: an unset optional is omitted at every depth. Omission follows the schema's optionality, not an output value of `undefined`: a required `z.undefined()` field remains present and survives `make(toJSON())`. A required transform that outputs `undefined` but cannot parse that output is rejected at construction, since no serialized value could rehydrate it. The constructor installs absent optional fields non-enumerable (still locked), and the freeze walk drops their `undefined` keys from the plain objects zod produced, copying one it cannot change (`.readonly()` or a non-configurable key). It records a copy before descending so a cycle points to the canonical copy. Computed fields see the canonical data, and aggregate folds see the same projection on live commands and replay. A change set or `diff` helper is deliberately not shipped: what a change means is the store's (`$unset`, `UPDATE … SET`), and two projections already answer it.

Computed callbacks and aggregate fold handlers see only declared fields, never placeholder or stored computed keys. When a union of objects has a unique matching literal discriminator, canonicalization uses that branch's optionality; if the branch is ambiguous, it omits an undefined key only when every possible branch declares it optional. A required undefined output is checked against its own field schema alone, so unrelated transforms run once per `make`.

The package's type behaviour is its product. `src/*.test-d.ts` guards the compile-time surface under this repository's TypeScript and `typescript-consumer` (5.9); the latter also compiles source so a circular alias in an exported namespace cannot hide behind this repo's newer compiler. `examples/entity-billing-domain/src/emit-guards.ts` is the consumer declaration-emission gate: its `typecheck` emits with this repository's TypeScript and with `typescript-consumer`, then checks the emitted declarations under the consumer compiler. Keep this gate when changing exported types, especially around branded fields, abstract roots, unions, factories and aggregates. Do not add `--skipLibCheck` to the emitted-output check.

`package.json` participates in the fixed Changesets group with every published package; do not introduce a separate version. Maintain `node >=22` as the published floor while the root may require a newer development Node. The guide lives under `docs/entity/`; old `https://btravstack.github.io/entity/` URLs need a redirect from the former site when this migration deploys.
