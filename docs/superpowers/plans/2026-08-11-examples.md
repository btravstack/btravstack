# `examples/` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an `examples/` workspace holding two private packages that boot the same `@btravstack/di` module under two different real runtimes, serving as both documentation and the package's first integration tests.

**Architecture:** `examples/http-api` owns the shared `AppModule` and a `Runtime` implemented over `node:http`; `examples/worker` depends on it and boots the same module under an in-memory queue `Runtime`. Both are private workspace packages following the `btravstack/di` and `btravstack/entity` convention.

**Tech Stack:** TypeScript 7.0.2, `unthrown`, `@btravstack/di`, `@btravstack/start` (all `workspace:*`/`catalog:`), vitest, `node:http` — no other runtime dependencies.

## Global Constraints

- **No runtime dependencies beyond `unthrown`, `@btravstack/di`, `@btravstack/start` and `node:` builtins.** No HTTP client library, no broker, no database. Use `fetch` (global in Node 20+) in specs.
- Both example packages are `private: true`. No changeset, nothing published.
- TypeScript `strict` + `exactOptionalPropertyTypes` + `noUncheckedIndexedAccess`; ESM-first; `moduleResolution: NodeNext` — relative imports end in `.js`.
- oxlint binding: no `interface` (use `type`), no `any` (use `unknown`). `@unthrown/oxlint` recommended rules apply, including `no-unhandled-result` and `no-catch-all-pattern`. A targeted `oxlint-disable` must carry a reason.
- Comment density SPARSE. No comments in JSON files.
- Conventional commits.
- The full repo gate must stay green: `pnpm format --check`, `pnpm lint`, `pnpm typecheck`, `pnpm knip`, `pnpm test`, `pnpm build`.
- Package naming: `@btravstack/start-example-<dir>`, matching `@btravstack/di-example-*`.

## The shipped API these examples compile against

Read it, do not guess:

```ts
const start: <X, E, Needs extends AnyPort>(
  module: Module<X, E, Scope>,
  options: StartOptions<Needs>,
  ...gate: [InstanceType<Needs>] extends [X] ? [] : [error: "UNSATISFIED RUNTIME NEEDS", missing: …]
) => RunningApp<E>;

type StartOptions<Needs extends AnyPort> = {
  readonly runtime: Runtime<Needs>;
  readonly clock?: Clock;
  readonly signals?: boolean;
  readonly probes?: { readonly port: number } | false;
  readonly preDrainDelayMs?: number;
  readonly drainTimeoutMs?: number;
  readonly onEvent?: EventSink;
};

type RunningApp<E> = {
  readonly exited: AsyncResult<ExitReport, E | RuntimeStartFailed>;
  readonly stop: () => void;
  readonly requestDrain: () => void;
  readonly phase: () => Phase;
  readonly ready: () => boolean;
  readonly probePort: () => Promise<number | undefined>;
};

type Runtime<Needs extends AnyPort> = {
  readonly name: string;
  readonly needs: readonly Needs[];
  readonly start: (host: RuntimeHost<Needs>) => AsyncResult<Serving, RuntimeStartFailed>;
};
type RuntimeHost<Needs extends AnyPort> = {
  readonly ctx: Context<InstanceType<Needs>>;
  readonly run: RunUnit<Needs>;
};
type Serving = {
  readonly drain: (signal: AbortSignal) => AsyncResult<void, never>;
  readonly stop: () => AsyncResult<void, never>;
};
```

Note `Runtime` is parameterised by port **classes** while `ctx` is `Context<InstanceType<Needs>>`. `needs: [Router]` gives `Needs = typeof Router`.

- [ ] **Step 5: Implement `src/app.ts`**

Four ports and one module. `Router` is the port the HTTP runtime will declare as its need — that is what makes `Needs` non-empty.

```ts
import { Module, Port, Provider, type ServiceOf } from "@btravstack/di";
import { Err, Ok, TaggedError, type AsyncResult } from "unthrown";

export type Order = { readonly id: string; readonly quantity: number };

export class OrderNotFound extends TaggedError("OrderNotFound")<{
  readonly id: string;
}> {
  override message = `no order with id ${this.id}`;
}

export class DuplicateOrder extends TaggedError("DuplicateOrder")<{
  readonly id: string;
}> {
  override message = `order ${this.id} already exists`;
}

export class Logger extends Port("Logger")<{
  readonly info: (message: string) => void;
  readonly lines: () => readonly string[];
}> {}

export class OrderRepository extends Port("OrderRepository")<{
  readonly save: (order: Order) => AsyncResult<Order, DuplicateOrder>;
  readonly find: (id: string) => AsyncResult<Order, OrderNotFound>;
}> {}

export class PlaceOrder extends Port("PlaceOrder")<{
  readonly execute: (
    id: string,
    quantity: number,
  ) => AsyncResult<Order, DuplicateOrder>;
  readonly find: (id: string) => AsyncResult<Order, OrderNotFound>;
}> {}

export type Handler = (
  body: unknown,
) => AsyncResult<unknown, DuplicateOrder | OrderNotFound>;

export class Router extends Port("Router")<{
  readonly route: (method: string, path: string) => Handler | undefined;
}> {}
```

The `Logger` adapter is what reads the ambient record — import `currentUnit` from `@btravstack/start` and prefix each line with the trace id:

```ts
const loggerProvider = Provider(Logger)({
  sync: () => {
    const lines: string[] = [];
    return {
      info: (message) =>
        lines.push(`[${currentUnit()?.traceId ?? "-"}] ${message}`),
      lines: () => lines,
    };
  },
});
```

The repository is an in-memory `Map`; `save` returns `Err(new DuplicateOrder({ id }))` when the id is present, `find` returns `Err(new OrderNotFound({ id }))` when it is absent. `PlaceOrder` depends on `[OrderRepository, Logger]` and logs before delegating. `Router` depends on `[PlaceOrder]` and routes `POST /orders` to a handler calling `execute`, and `GET /orders/:id` to one calling `find`; anything else returns `undefined`.

`AppModule` provides all four and exports `Router`, `PlaceOrder`, `Logger` (the repository stays private — that is `di`'s module privacy, worth demonstrating).

- [ ] **Step 1: Write the failing runtime spec**

`examples/http-api/src/http-runtime.spec.ts` — the assertions, each of which must hold:

1. **A real request reaches the DI-wired use case.** Start the app on `port: 0`, read the bound port, `POST /orders` with `{"id":"o-1","quantity":2}`, expect `201` and the order as JSON.
2. **A domain `Err` maps to a status at the edge.** POST the same id twice; the second is `409`, body `{"error":"DuplicateOrder"}`. `GET /orders/missing` is `404`.
3. **An unknown route is `404`** without touching the application.
4. **A defect maps to `500`.** Add a route whose handler throws; assert `500` and that the process did not die.
5. **Each request runs in its own unit.** After two requests, `ctx.get(Logger).lines()` shows two DIFFERENT trace ids — proving `host.run` opened a unit per request and the ambient record is per-unit.
6. **Draining lets an in-flight request finish.** Start a slow request, call `app.requestDrain()`, assert the slow response still arrives with `200`, and that `ExitReport.drain` is `{ inFlightAtStart: 1, completed: 1, abandoned: 0 }`.
7. **A request arriving after the drain has stopped acceptance is refused** (connection refused or a non-2xx — assert whichever the implementation actually produces, and say which in the report).
8. **A hung request is aborted at the deadline and counted.** With `drainTimeoutMs: 0`, a never-resolving handler yields `abandoned: 1`.
9. **The probe server answers alongside a real runtime.** With `probes: { port: 0 }`, read `await app.probePort()`, then `GET /livez` → `200 ok` and `GET /readyz` → `200 ready` while serving. After `requestDrain()`, `/readyz` is `503` while the HTTP runtime is still finishing in-flight work — the ordering the drain's first beat exists for, observed end to end for the first time.
10. **The probe port is separate from the application port.** Assert `await app.probePort()` differs from the HTTP runtime's bound port — the reason probes are process-level rather than a route on the public server.

Use `preDrainDelayMs: 0` in every spec except where the delay itself is under test, so the suite stays fast.

- [ ] **Step 3: Implement `src/http-runtime.ts`**

The shape, with the load-bearing parts spelled out:

```ts
import { createServer, type Server } from "node:http";
import type { Runtime, RuntimeHost, Serving } from "@btravstack/start";
import { RuntimeStartFailed } from "@btravstack/start";
import { Ok, fromSafePromise, type AsyncResult, type Result } from "unthrown";

import { Router } from "./app.js";

export const httpRuntime = (options: { readonly port: number }): Runtime<typeof Router> => ({
  name: "http",
  needs: [Router],
  start: (host: RuntimeHost<typeof Router>) => { … },
});
```

Inside `start`:

- `const router = host.ctx.get(Router);`
- Create the server. For each request: read the body, look up the handler, and if none reply 404 without opening a unit. Otherwise:

```ts
const outcome = await host.run(
  { kind: "http", id: `${request.method} ${request.url}` },
  (_ctx, signal) => handler(body, signal),
);
```

- Map the outcome with `match`, and note this is the ONLY place a `Result` becomes a status:

```ts
outcome.match({
  ok: (value) => respond(response, 201, value),
  errCases: (m) =>
    m
      .with(P.tag("DuplicateOrder"), (e) =>
        respond(response, 409, { error: e._tag }),
      )
      .with(P.tag("OrderNotFound"), (e) =>
        respond(response, 404, { error: e._tag }),
      ),
  defect: () => respond(response, 500, { error: "InternalError" }),
});
```

Every error case is named — no `P._`. That is the repo's own `no-catch-all-pattern` rule, and demonstrating it is part of the example's job.

- `Serving.drain(signal)` closes the listener so no new connections are accepted while in-flight requests finish, and resolves `Ok(undefined)`. `Serving.stop()` closes the server and destroys remaining sockets. Track open sockets so `stop` can close them; a `node:http` server's `close` waits for keep-alive connections otherwise and the test would hang.
- A bind failure resolves `Err(new RuntimeStartFailed({ runtime: "http", cause }))`.

- [ ] **Step 3: Implement `src/queue-runtime.ts`**

An in-memory queue: `start` takes the jobs, drains them one at a time through `host.run`, and records each outcome as `acked` / `deadLettered`. `drain(signal)` stops pulling new jobs (set a flag) and resolves; `stop()` clears the queue. Expose `acked()` / `deadLettered()` for the spec to assert against — the runtime object is the example's own type, so extra methods on it are fine.

Map outcomes with the same exhaustive matcher, to a different transport:

```ts
outcome.match({
  ok: () => acked.push(job.id),
  errCases: (m) =>
    m
      .with(P.tag("DuplicateOrder"), () => deadLettered.push(job.id))
      .with(P.tag("OrderNotFound"), () => retried.push(job.id)),
  defect: () => deadLettered.push(job.id),
});
```
